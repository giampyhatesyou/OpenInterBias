# Intersectional Bias Schema and Concept Definition

This document details the definition of intersectionality used in this extension and the schemas for data models and outputs.

---

## 1. Defining Intersectionality for OpenBias

Intersectionality in generative image bias refers to the joint probability distribution of two or more demographic/contextual attributes when conditioned on a context or generated by a model. 

For two attributes $A$ (with classes $a_1, a_2, \dots, a_M$) and $B$ (with classes $b_1, b_2, \dots, b_N$), the joint distribution is defined by the probabilities $P(A=a_i, B=b_j)$.

We define two distinct metrics to capture different aspects of intersectional bias intensity:

### A. Normalized Joint Entropy
Measures the overall skew/uniformity of the joint distribution. 
If the model only generates a specific combination (e.g. only White Male doctors), the joint entropy is low (intensity is high). If it generates all combinations uniformly, the joint entropy is high (intensity is low).

$$\text{Joint Entropy } H(A, B) = -\sum_{i=1}^{M} \sum_{j=1}^{N} P(a_i, b_j) \log_2 P(a_i, b_j)$$

We normalize the joint entropy by its maximum possible value $\log_2(M \times N)$ to ensure the score is bounded in $[0, 1]$:

$$\text{Normalized Joint Entropy } H_{norm}(A, B) = \frac{H(A, B)}{\log_2(M \times N)}$$

$$\text{Joint Intensity Score} = 1 - H_{norm}(A, B)$$

### B. Mutual Information (MI)
Measures the synergistic dependency/interaction between the two attributes. It quantifies how much knowing one attribute reduces uncertainty about the other. If $A$ and $B$ are independent (e.g., the gender distribution is identical across all races), Mutual Information is $0$. If they are highly dependent, MI is high.

$$I(A; B) = \sum_{i=1}^{M} \sum_{j=1}^{N} P(a_i, b_j) \log_2 \left( \frac{P(a_i, b_j)}{P(a_i) P(b_j)} \right)$$

We normalize Mutual Information to the range $[0, 1]$ using the minimum of the individual attribute entropies:

$$I_{norm}(A; B) = \frac{I(A; B)}{\min(H(A), H(B))}$$

## 2. JSON Schemas

### A. Joint Class and Proposal Schema
For each caption, the pipeline identifies pairs of proposed biases and represents the candidate as:

```json
{
  "caption_id": 12345,
  "caption": "A photo of a doctor",
  "bias_pair_name": "person gender x person race",
  "attribute_a": {
    "name": "person gender",
    "classes": ["male", "female"],
    "question": "What is the gender of the doctor?"
  },
  "attribute_b": {
    "name": "person race",
    "classes": ["white", "black", "asian", "indian"],
    "question": "What is the race of the doctor?"
  }
}
```

### B. Scoring Output Schema
The calculated scores are saved under:

```json
{
  "results": {
    "person gender x person race": {
      "context_free": {
        "joint_intensity": 0.421,
        "mutual_information": 0.156,
        "support_images": 120,
        "joint_distribution": {
          "male x white": 60,
          "male x black": 20,
          "female x white": 30,
          "female x black": 10
        }
      },
      "context_aware": {
        "mean_joint_intensity": 0.354,
        "mean_mutual_information": 0.112
      }
    }
  }
}
```
